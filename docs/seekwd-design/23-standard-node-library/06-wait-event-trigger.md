# 等待、事件与触发节点

## 等待的本质

等待节点把“暂时不能继续”变成持久化的运行状态，而不是阻塞一个进程。等待必须有恢复事件、超时、取消和失效语义。

## `wait.input`

等待符合 Schema 的人类或执行主体输入。输入请求有 ID、作用域、过期时间、提交者和验证器；重复提交使用幂等键。

## `wait.dependency`

等待其他节点、画布、目标或外部 Operation 的状态或输出。依赖引用必须包含版本、关联 ID、接受的终态和超时策略。

## `wait.timer`

等待绝对时间、相对时间或外部时间条件。计时器由持久化服务托管，进程重启不影响到期事件。

## `wait.event`

等待匹配事件过滤器。实例声明事件类型、版本、主题、去重键、游标、重放窗口和消费确认策略。

## `trigger.start`

将手动命令、计划、恢复或调用请求转换为目标入口。触发器必须校验输入、身份、幂等和当前画布版本。

## `trigger.event`

订阅事件并创建新的 Run 或激活已有 Run 分支。触发策略声明是否允许并发、合并窗口、丢失事件处理和取消传播。

## 事件等待的竞态

注册订阅和检查已有事件必须具备原子或可恢复语义，避免事件在“检查”和“订阅”之间丢失。恢复时使用游标重新对账。

## 超时

超时触发指定路径，不默认标记主目标失败。超时路径可以重试、替代、请求用户、补偿或结束；决策必须记录在 Run Event。
