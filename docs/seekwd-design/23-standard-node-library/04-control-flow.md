# 控制流节点

## `control.sequence`

只表达显式先后，不携带业务数据。目标节点在源节点达到指定终态后才进入候选队列；源节点失败时按失败策略选择错误路径或阻断。

## `control.condition`

读取声明的只读输入，输出判定结果、DecisionRecord 和选中的分支。求值错误不能默认当作 false。

## `control.switch`

根据有限的、可审计的路由键选择路径。未命中、多个命中和路由键缺失都必须有明确处理。

## `control.join`

合并多条前置依赖。实例声明：等待全部、等待任意、等待满足数量、失败是否阻塞、部分结果是否可用。Join 必须防止永远等待，所有输入都要有终止或超时语义。

## `control.race`

接受第一个满足条件的结果，取消或隔离未获胜分支。未获胜分支的外部副作用不能假设已撤销；需要补偿时显式连接 Compensation。

## `control.merge`

将数据和控制路径合成一个明确的输入契约。Merge 不能通过覆盖同名字段隐藏冲突，必须使用声明的 merge policy。

## `control.stop`

结束指定范围：当前分支、子图、画布运行或目标运行。停止原因、是否触发补偿、是否保留输出和是否传播到父运行都必须配置。

## `control.noop`

显式占位或断点，不产生业务副作用。它可以作为人工编辑的连接锚点，但不能被用来绕过必需验证。

## 控制和数据分离

一条控制边不能被当作数据存在的证明，一条数据边不能被当作执行顺序的证明。需要两者时必须创建两条具有独立语义的边。
