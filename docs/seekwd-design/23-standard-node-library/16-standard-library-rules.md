# 标准节点库治理规则

## 何时新增标准节点

只有当一个语义跨领域、无法用现有标准节点清晰组合、会被 Planner 高频需要，并且能给出稳定输入输出及错误契约时，才考虑新增标准节点。

## 何时使用扩展节点

领域知识、专业工具、具体应用、外部能力、用户脚本和实验性能力必须作为扩展节点或复合节点，不能污染标准库。

## 命名规则

```text
namespace.category.action
```

标准库使用保留 namespace，例如 `control`、`data`、`state`、`loop`、`wait`、`human`、`agent`、`canvas`、`verify`、`error`、`cache`、`observe`、`debug`、`run`。名称描述责任，不描述某个供应方或实现技术。

## 版本规则

修复内部实现且不改变契约可以发布补丁版本；新增可选字段使用兼容次版本；改变端口、输出含义、错误语义、权限或副作用需要不兼容主版本，并提供迁移方案。

## 最低测试

每个节点版本必须有：Schema 测试、状态机测试、错误测试、权限测试、取消测试、重试或幂等测试、Artifact 血缘测试和至少一个与其他标准节点组合的图测试。

## 去除节点

标准节点不能直接删除。先标记 deprecated，提供替代和迁移工具，等待没有已发布画布或活动运行引用后才可归档。
