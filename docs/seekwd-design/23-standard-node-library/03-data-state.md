# 数据与状态节点

## 数据节点共同规则

数据节点只负责值的创建、选择、转换和聚合，不应暗中触发外部副作用。需要副作用的操作必须使用 Action、Tool 或 Code 节点。

## `data.constant`

创建不可变值。常量带 Schema、来源、敏感度和生命周期。运行中不能被下游节点修改。

## `data.compose`

按目标 Schema 组装对象或集合。字段来源必须明确；缺失必填字段、重复字段和敏感度冲突都返回结构化错误。

## `data.select`

从结构化值或 Artifact 元数据中选择字段。选择表达式是纯的；读取内容必须受输入 Artifact 的访问策略约束。

## `data.transform`

执行声明的有限纯转换。转换定义包括输入输出 Schema、复杂度上限、版本和错误映射。复杂推理、网络访问和文件写入不能隐藏在 Transform 内。

## `data.map` 与 `data.filter`

只处理有限集合，必须声明最大元素数、顺序、并发和失败策略。单个元素失败可以选择终止、跳过、收集错误或交给错误分支，但不能静默丢失。

## `state.set` / `state.get`

状态必须声明作用域：节点、画布、运行、目标、工作区或用户。默认只允许当前运行作用域；跨运行和全局状态需要额外策略、版本和并发控制。

## `state.reduce`

使用声明的纯聚合器处理多值。聚合器要定义空集合、类型不一致、顺序、浮点误差和部分结果语义。

## 状态一致性

状态写入使用版本号或条件写入。恢复、重试和并发分支必须明确读取哪个 revision；不能因为读取了“最新状态”就破坏历史重放。
