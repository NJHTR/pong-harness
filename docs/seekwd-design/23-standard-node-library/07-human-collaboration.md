# 人类协作节点

## 共同契约

人类节点和自动节点使用相同的输入、输出、状态、证据和审计模型。区别是执行主体为 Human，而不是绕过 Runtime。

## `human.input`

请求一组符合 Schema 的值或资源。必须有问题说明、用途、作用域、默认行为、完成条件、过期时间和隐私提示。

## `human.choice`

展示结构化候选方案，记录候选版本、比较维度、用户选择、未选原因和选择时间。不得只保存自然语言答案而失去候选上下文。

## `human.approval`

请求具体 ActionRequest 或 GraphPatch 的授权。审批绑定动作摘要、资源、配置、图版本、运行和有效期；批准后生成一次性或有界 ApprovalGrant。

## `human.review`

请求用户查看结果、证据、差异或质量报告。用户可以确认、提出修改、标记问题或退回上一步。审查意见应成为结构化反馈。

## `human.takeover`

暂停自动执行，把节点或子图的控制权交给人类。接管范围、允许操作、提交结果、证据和交还条件必须明确。

## `human.feedback`

收集评价、修改和拒绝原因，供当前运行和后续技能改进使用。反馈不能直接覆盖成功标准或安全策略。

## 无响应

请求过期、用户拒绝、用户取消和用户未响应是四种不同结果。每种结果都必须有下游策略，不能永远留在等待状态。
