# 复合节点、画布调用与图变更节点

## `canvas.call`

调用一个精确或兼容版本范围内的画布，并等待其公开输出或指定终态。

配置：目标画布引用、入口、输入映射、输出映射、超时、重试、取消传播、幂等键和错误策略。

输出：子 RunHandle、公开输出、事件和结构化终态。调用方不能读取目标画布私有节点状态。

## `canvas.trigger`

启动目标画布后继续当前分支。输出至少含子 RunHandle 和关联 ID；是否监听结果由显式 `canvas.wait` 或事件边决定。

## `canvas.wait`

等待 Canvas Call、Canvas Trigger 或事件订阅的结果。必须声明接受的终态、结果映射、超时、取消和结果未知处理。

## `canvas.patch`

创建或应用 GraphPatch。输入包括 base graph version、操作集合、原因、影响分析、风险和验证计划。实际应用仍需经过 Graph Service 和 Policy。

## `composite.expand`

把一个高层节点替换为符合接口的内部子图。展开产生新 CanvasVersion 或 RunPatch，并保存原节点与子图的来源、输入输出映射和历史关联。

## `composite.compose`

把一组连通节点提取为复合节点。节点组对外的输入、输出、事件、错误和权限边界自动计算后仍要人工或静态校验。不能静默丢弃跨边界控制关系。

## 模块边界

复合节点和画布调用都只通过公开接口传递值、事件和证据摘要。调用方可以选择可检查或可编辑的封装等级，但封装等级不改变运行语义。
