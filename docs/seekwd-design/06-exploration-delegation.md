# 未知能力探索与执行单元委派

## 探索策略

当用户描述一个未知对象、应用或能力时，Agent 不依赖固定的发现顺序，而是根据目标、风险、可观测性、授权范围和成本选择探索方式。探索可以查询已知目录、观察环境、询问其他执行单元、请求用户线索，或构造低风险探测任务。

## 能力缺口

当当前执行单元缺少必要能力时，Agent 可以寻找替代能力、委派给其他执行单元、请求用户补充信息或接管、创建临时实现并验证，或者调整目标与执行计划。具体技术手段属于可插拔适配器，不写入核心 Agent 语义。

## 委派任务契约

```text
goal
scope of files / windows / websites
allowed actions
forbidden actions
success evidence
max steps / timeout / budget
parent run and cancellation policy
```

返回任务句柄、进度、观察证据、Artifact、错误和取消句柄。

## 能力实验画布

没有可信工具时，Agent 创建能力实验画布：

```text
定义输入输出契约
  -> 生成或组合实现
  -> 准备验证样本
  -> 在受控上下文执行
  -> 质量评估
  -> 修复失败
  -> 发布临时或正式节点版本
```

一次成功的探索流程可以保存为适配器，但外部应用和自动生成代码永远保留来源、版本和信任等级。
