# 本地持久化布局

## 逻辑存储区

```text
identity/       设备、用户、本地会话和密钥引用
definitions/    节点、能力、Schema、画布和版本
runs/           Run、NodeRun、事件、检查点和等待记录
artifacts/      Artifact 内容、revision、索引和血缘
projections/    搜索、列表、时间线和统计投影
memory/         记忆、技能、回归样本和信任记录
extensions/     扩展清单、安装状态、沙箱数据和日志
audit/          审计事实和完整性证明
backups/        用户可导出的加密备份
```

这是逻辑布局；实现可以使用数据库、文件系统和对象存储的组合，但每个区域必须声明事实来源、备份策略和恢复顺序。

## 工作区与应用数据分离

用户工作区资源与 Seekwd 应用数据分开。工作区由用户管理，应用数据由 Host 管理；删除或切换工作区不能误删另一方。Artifact 可以引用工作区资源，但必须记录外部路径、校验和和访问策略。

## 事务顺序

任何节点输出采用：预留 -> 写内容 -> 提交 revision -> 写血缘 -> 发布 NodeResult -> 写终态事件。状态和输出引用不能出现半提交可见状态。

## 备份

备份至少包含目标、画布版本、节点定义引用、运行事实、Artifact 元数据、记忆、技能和策略；大内容按用户选择增量或完整备份。秘密默认不随普通备份导出，使用单独的加密流程。

## 导入导出

导出的画布必须标记依赖、缺失能力、版本范围、敏感字段和目标环境。导入先进入 Draft 和隔离校验，不能因为文件中带有“自动执行”标记而直接启动。
