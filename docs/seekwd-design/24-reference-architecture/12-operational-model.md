# 运维模型

## 常态运行

Host 定期执行健康检查、事件投影、队列租约、Artifact 引用、扩展状态、备份和过期清理。所有后台任务都有预算和可暂停状态。

## 诊断入口

用户和支持人员可以生成诊断包，包含版本、健康状态、运行 ID、事件摘要、错误、指标和脱敏配置；不默认包含秘密、完整文件或完整对话。

## 清理

清理分为缓存、临时执行上下文、过期等待、运行日志、Artifact 和审计数据，每类拥有独立保留策略。清理任务遵守引用检查、用户锁定和合规保留。

## 背压

当事件、日志、流、Artifact 或队列增长超过阈值时，系统按优先级暂停生产者、降低详细度、写入磁盘或请求用户，不静默丢弃关键状态事件。

## 资源配额

配额按用户、工作区、目标、画布、节点和执行上下文分层。超额后进入等待、降级或人工决策；配额重置和消费明细可查询。

## 支持边界

系统应区分“目标失败”“能力失败”“Host 失败”“扩展失败”“外部系统未知结果”和“用户取消”，让用户知道下一步是重试、恢复、替代还是人工处理。
