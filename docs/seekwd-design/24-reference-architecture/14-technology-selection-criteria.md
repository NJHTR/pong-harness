# 技术选型标准

这里暂不决定具体技术，先定义必须满足的能力。候选方案按以下标准比较：

## Host

- 可作为本地后台进程运行并安全升级。
- 提供可靠的本地 IPC、长连接、取消和流式传输。
- 支持文件、进程、环境和隔离上下文的受限访问。
- 崩溃恢复和资源清理可控。

## 存储

- 支持不可变版本、追加事件、条件写入和事务。
- 支持 Artifact 大内容与元数据分离。
- 支持备份、迁移、索引重建和离线运行。

## 执行隔离

- 能限制文件、网络、进程、资源和秘密。
- 能报告健康、取消、结果未知和资源消耗。
- 能把失败和副作用边界传回 Runtime。

## 前端

- 支持大型图、嵌套图、实时事件和局部更新。
- 草稿、事实投影和离线队列明确分离。
- 能展示版本差异、证据、日志、审批和父子运行。

## 扩展

- 支持发现、签名或完整性、权限声明、版本兼容、健康检查和禁用。
- 扩展失效不会拖垮核心 Host。
- 能在不改变核心 Schema 的情况下增加新能力。
