# 安装、升级与恢复

## 安装阶段

```text
preflight      检查系统、权限、磁盘和已有版本
installing     写入应用、Host 和基础资源
initializing   创建设备身份、数据目录和初始策略
migrating      执行数据迁移
verifying      运行完整性和启动检查
ready          可连接和运行
```

安装失败必须可清理或回滚，不能留下一个 Host 以为已健康但数据未初始化的状态。

## 升级原则

升级前创建可验证备份和迁移计划；先停止接受新副作用命令，再等待或安全暂停活动 Run。升级不应强制取消可恢复任务。

## 数据迁移

迁移脚本必须版本化、幂等、可检查和有回滚或恢复说明。定义版本、事件版本、Schema 版本和存储版本分别迁移，不能只依赖应用版本号。

## 回滚

回滚应用代码不一定能回滚已经迁移的数据。系统要区分代码回滚、Schema 前向兼容、数据恢复和运行恢复，并在升级前验证组合是否可行。

## 灾难恢复

恢复目标包括：目标和画布可读取、运行事实可重建、Artifact 引用不悬空、权限决定可审计、活动外部操作可对账。恢复后先进入 recovering，不直接恢复所有自动动作。

## 版本兼容

Workbench、Host、Core、扩展和数据协议分别协商兼容范围。客户端升级不能强迫 Host 立即升级；不兼容时提供只读、迁移或安全停止路径。
