# 架构原则

## 本地优先

用户的目标、画布、运行、Artifact、授权和审计默认由用户设备控制。离线时允许编辑、查看历史、运行本地可用能力和恢复任务；需要外部能力时，系统明确显示连接、数据范围和失败状态。

## 控制平面与执行平面分离

```text
Control Plane
  目标、图、策略、调度、状态、审计、权限和用户交互

Execution Plane
  节点实际执行、外部能力调用、代码运行、资源消耗和流输出
```

执行平面不能直接改写控制平面事实；控制平面也不能假装执行已经完成。二者通过 ExecutionHandle、NodeResult、Observation 和事件协调。

## UI 与事实分离

Workbench 是可替换客户端。它可以离线缓存、编辑草稿和显示运行投影，但不能成为 Goal、Run、Policy 或 Artifact 血缘的唯一事实来源。

## 最小授权和最小暴露

每个执行上下文、扩展和会话只获得完成当前节点所需的最小权限、数据和时间。宿主能力不能因某个 UI 或 Agent 可见而自动全局开放。

## 可恢复优先

任何长操作、等待、执行器调用、文件写入和跨边界通信都假设可能中断。架构优先记录恢复所需事实，再启动不可逆副作用。

## 可替换实现

组件间依赖稳定契约；数据库、UI、模型、执行器、扩展协议、打包器或网络实现可以替换，不能改变 Goal、Graph、Run、Artifact、Policy 和 Evidence 的语义。
