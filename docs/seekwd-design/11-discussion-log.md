# 讨论沉淀记录

## 2026-09-17：从工作流画布升级为开放式 Agent Harness

本次确认的核心变化：

- 产品不是固定节点工作流，而是可以探索未知能力的 Agent 工作台。
- 任一 Agent 可能缺少完成目标所需的能力，并可在运行时发现、委派或构造补足能力。
- 找不到能力时，Agent 可以创建代码、适配器、节点和能力实验画布。
- 复杂节点可以展开、拆分、调试；多个节点和画布可以重新封装。
- 外部能力不应被当作产品边界，而应通过能力发现和委派接入。
- “像人一样”被重新定义为观察、规划、行动、验证、修复、记忆和协作闭环。

## 2026-09-17：建立目标执行系统的内层设计

- 将抽象目标定义为可版本化的 GoalRequest，而不是一条不可验证的提示词。
- 将目标执行拆为规范化、上下文、拆解、能力发现、图编译、调度、观测、验证、修复、协作、交付和沉淀。
- 定义 GoalVersion、GraphVersion、Run、NodeRun、Artifact、Evidence 和 PermissionDecision 等核心实体。
- 明确目标优先于实现方式，具体技术只作为可插拔能力来源。
- 增加从模块职责到验收条件的开发拆解，作为后续实现的基准。

## 2026-09-17：明确人类与 Agent 的双向协作

- 人类可以完全搭建和执行，也可以只搭建框架、把局部交给 Agent，或与 Agent 共同完成。
- Agent 可以自动建图和执行，但不能成为唯一操作主体。
- 构建主体和执行主体是两个独立维度，支持人工搭建后 Agent 执行、Agent 搭建后人工调试，以及运行中的节点级接管。

## 2026-09-17：冻结节点与画布的正式规范方向

- 画布被定义为可调用、可组合、可版本化的图模块，而不只是可视化编辑页面。
- 节点被定义为最小可调度责任单元，必须具备输入、输出、执行、验证、失败和权限契约。
- 节点、端口、边、复合节点、运行和展示数据彼此分层，避免 UI 状态改变运行语义。
- 数据、控制、事件、等待、错误和补偿关系使用不同边语义，禁止万能隐式连线。
- 增加节点与画布的规范化 Schema、编辑协作规则、运行语义、版本持久化和验收不变量。

## 2026-09-17：补齐节点画布依赖的基础规范

- 将身份、引用、版本、时间、类型、Schema、事件、消息、状态机和错误定义为独立基础语义。
- 明确执行上下文、主体、委托、策略、审批、表达式、映射和存储一致性边界。
- 定义扩展协议、执行器契约、Agent 契约、观测模型和测试契约。
- 明确 UI、Planner、Runtime、Executor、Storage 和 Adapter 的依赖方向与禁止耦合。

## 2026-09-17：定义核心运行时服务与恢复边界

- 按事实所有权划分目标、图、运行、执行、产物、观察、验证、策略、记忆、投影和审计服务。
- 定义 Command / Query、长操作、事件订阅、幂等和并发控制的统一边界。
- 定义 Agent 的结构化输入输出，禁止通过非结构化文本直接改变图或权限。
- 定义崩溃恢复、孤儿执行、外部结果未知和补偿的处理方式。
- 建立面向扩展协议、威胁模型和核心能力完成定义的发布门槛。

## 2026-09-17：建立标准节点库

- 定义输入输出、数据状态、控制流、循环、等待事件、人类协作、Agent、能力、画布、验证、错误、缓存和调试等跨领域原语。
- 为每个节点族定义责任、端口、失败、等待、重试、验证和运行规则。
- 定义标准节点 Manifest、命名空间、版本、兼容、测试和弃用治理规则。

## 2026-09-17：定义本地优先参考架构

- 将 Workbench、Pong Host、Harness Core、执行上下文和扩展明确为不同责任边界。
- 定义本地 IPC、会话、持久化、队列、扩展、网络、升级、恢复和日常运维的语义。
- 固化控制平面与执行平面分离，以及长期任务不依赖 UI 存活的架构原则。

## 2026-09-17：形成可执行的参考实现蓝图

- 选定 Tauri 2、React + TypeScript、Rust + Tokio、SQLite + WAL 和内容寻址 Artifact Store 作为默认实现，而非领域规范本身。
- 明确 Workbench、Pong Host、Harness Core、Runtime、Policy、Artifact、Agent、Extension 与 Worker 的代码边界。
- 补充 IPC 信封、事件游标、Artifact 句柄、扩展消息、Worker 取消与恢复的实现要求。
- 制定从可持久化核心、图语言、运行时、Host/客户端、Agent/扩展到强化能力的依赖顺序和验收标准。
