# 不变量与验收条件

## 结构不变量

1. 每个节点实例引用一个存在的节点定义版本。
2. 每条边引用存在的源端口和目标端口。
3. 所有必需输入都有显式来源、默认值或人工输入路径。
4. 公开画布接口与内部映射一致。
5. 普通边不能形成未声明的循环。

## 运行不变量

1. Run 只执行一个明确的 CanvasVersion。
2. NodeRun 只使用该运行快照中解析过的配置、能力和策略。
3. 节点状态转换符合状态机，并且每次转换都有事件。
4. 等待、重试、取消和失败都有终止或恢复条件。
5. 父运行取消会按声明策略传播到子运行。

## 数据不变量

1. 大型数据通过 Artifact 引用传递。
2. 端口值带 Schema、来源、版本和敏感度。
3. 最终产物可反查到 NodeRun、输入和验证证据。
4. 历史运行不受后续编辑、发布或删除影响。

## 安全不变量

1. 节点不能扩大授予它的权限和资源作用域。
2. 未经授权不能执行有副作用的动作。
3. 外部输入不能覆盖系统策略或成功标准。
4. 审批绑定到具体运行、节点、配置和资源范围。
5. 新能力必须带信任等级和验证证据。

## 人机协作不变量

1. 人类和 Agent 的操作都通过相同的图、运行和审计模型。
2. 构建主体和执行主体独立记录。
3. 控制交接不丢失检查点、输入、输出和待决策。
4. 人工提交的结果仍需经过相同的成功标准验证。

## 最小验收场景

- 人类创建一个包含输入、处理、验证和输出的画布并成功运行。
- Agent 根据目标创建同等契约的画布，人类修改其中一个节点后运行。
- 一个高层节点展开为子图，再封装回复合节点，历史运行保持可追溯。
- 节点运行中进入等待，用户补充输入后从检查点恢复。
- 节点失败后 Agent 生成 GraphPatch，只重跑受影响分支。
- 两张画布通过调用、事件、数据映射和等待完成一次父子运行。
- 人类接管一个节点后交还 Agent，主体和证据完整可查。
- 草稿修改、版本发布和运行并发进行时，历史运行结果不改变。
