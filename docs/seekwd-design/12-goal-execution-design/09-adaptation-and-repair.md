# 动态适应与修复

## 失败分类

```text
input_invalid       输入缺失或不符合契约
planning_invalid    计划不能覆盖目标
capability_missing  没有满足需求的能力
environment_invalid 环境缺失或版本不兼容
authority_denied    权限或审批不足
execution_failed    执行单元失败
observation_stale   观察结果过期
verification_failed 结果未达到成功标准
resource_exhausted  预算、时间或资源耗尽
external_unavailable 外部依赖不可用
```

## 修复闭环

```text
捕获失败
  -> 收集输入、日志、观察、环境和历史证据
  -> 生成原因假设
  -> 验证原因假设
  -> 生成多个修复方案
  -> 估算风险、成本和影响范围
  -> 选择或请求用户选择
  -> 生成 Graph Patch
  -> 校验并应用
  -> 只重跑受影响分支
  -> 重新验证
```

## 修复限制

修复 Agent 不应为了让状态变绿而放宽成功标准、删除验证节点或隐瞒失败。任何修改目标、约束、权限、交付物或成功标准的操作都属于目标变更，需要产生新目标版本或人工确认。

## 替代路径

替代能力必须保持相同的输入输出和成功契约；若质量、权限、成本或可解释性发生变化，必须记录偏差并重新评估是否可接受。

## 人类接管与恢复

修复过程中可以把某个节点、子图或决策点转交给人类完成。人类提交的结果必须使用相同的输入输出契约，并附带操作说明或证据；Agent 可以继续验证、执行下游或提出下一次修复，但不能覆盖人类已经确认的结果。

## 学习边界

修复成功不等于新方案已可信。只有通过回归验证、敏感信息清理和发布审查后，才可以沉淀为工作区或全局技能。
