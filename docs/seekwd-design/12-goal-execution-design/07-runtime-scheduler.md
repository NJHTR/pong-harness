# 运行时调度器

## 调度器职责

Pong Harness 调度器不负责理解业务内容，它负责根据图、状态、权限、资源和事件可靠地推进运行：

```text
加载冻结图版本
  -> 建立运行上下文
  -> 计算可运行节点
  -> 排队并分配执行上下文
  -> 收集结果和事件
  -> 更新依赖状态
  -> 创建检查点
  -> 推进、等待、失败或完成
```

## 节点执行包络

```text
ExecutionEnvelope
  runId / nodeRunId / correlationId
  graphVersion / nodeVersion
  input snapshot
  authorized scopes
  selected execution context
  remaining budgets
  cancellation signal
  required evidence
  output policy
```

节点实现不能自行扩大包络中的权限或作用域。

## 可运行判定

节点仅在以下条件同时满足时进入队列：

1. 所有必需数据前置节点已经成功，或显式允许部分输入。
2. 所有控制前置条件已经满足。
3. 条件边判定为可进入。
4. 所需环境和权限已经准备好。
5. 节点没有被禁用、取消或过期。
6. 幂等策略允许本次运行。

## 并发与资源

调度器按全局、画布、目标、能力和执行上下文分别限制并发。资源不足时进入排队或等待，不通过无限创建 Agent 来掩盖资源问题。流式输出必须支持背压、截断策略和取消传播。

## 检查点与恢复

检查点至少保存图版本、节点状态、输入引用、输出引用、队列、重试计数、等待关系、权限决定和外部任务句柄。恢复后要重新检查外部状态和授权有效期，不能盲目重放有副作用的动作。

## 幂等和副作用

节点定义声明是否幂等、是否有副作用、是否支持补偿。非幂等动作必须有幂等键、确认状态或人工确认；重试不能默认重复产生外部副作用。
