# 抽象目标 A：全流程运行推演

本文件只展示系统如何处理一个未知领域的目标，不指定具体行业、应用或工具。

## 目标输入

```text
用户：请完成目标 A，并把结果交付给我。
```

系统首先保留原话，然后创建：

```text
目标意图：完成目标 A
交付物：待确认
成功标准：待提炼
约束：待提炼
资源范围：当前授权范围
风险容忍度：默认保守
```

## 阶段一：规范化

Agent 解析目标中的对象、动作、结果、期限、格式和隐含前提，形成候选成功标准。若缺少的信息不会改变风险或结果，可以暂时使用显式假设；否则创建 `Input Request` 节点并等待用户。

输出：`GoalVersion-1`、约束集、假设集、问题清单。

## 阶段二：拆解

Agent 先按交付物建立结果树，再反推中间结果，最后为每个结果定义任务契约：输入、输出、完成条件、依赖、权限、环境和失败策略。

输出：目标树、任务 DAG、验证任务、人工介入点。

## 阶段三：发现能力

对每个任务生成 `CapabilityNeed`，搜索现有能力并评估契约兼容性、证据、成本、风险和可取消性。如果没有合适能力，则选择替代、委派、询问用户或创建能力实验图。

输出：能力选择记录、能力缺口或新能力候选。

## 阶段四：生成图

Planner 将任务 DAG 编译为 Graph Version：数据边传递结果，控制边表达顺序，事件边表达触发，等待边表达依赖，验证节点表达成功标准，错误路径表达修复和人工介入。

运行前执行端口、配置、循环、权限、环境、预算和终止性检查。

输出：`GraphVersion-1`、静态检查报告、待审批动作。

## 阶段五：执行

调度器按照依赖选择可运行节点，创建 `ExecutionEnvelope`，分配执行上下文并保存检查点。并行节点受资源和策略限制；流式节点受背压和取消控制。

每个节点完成后产生状态、输出、观察和证据，驱动下游依赖重新计算。

## 阶段六：不确定性和失败

如果节点失败，Agent 不直接盲目重试，而是分类原因，读取相关证据，提出修复、替代、补充输入或人工接管方案。修改图必须通过 Graph Patch，并只影响受影响分支。

## 阶段七：验证和交付

验证器逐项检查成功标准。若全部阻塞性标准通过，生成交付清单，打包产物、摘要、证据、未解决问题和运行关联。若只有部分标准通过，状态保持未完成，不用“看起来完成”替代验证。

## 阶段八：沉淀

清理敏感数据后，将稳定的输入输出和执行关系生成技能候选，建立回归样本并验证可重复性。原始运行、目标版本和图版本永久保留关联，技能发布不会改写历史。

## 运行结束时用户能看到

```text
目标状态
完成了哪些子目标
最终交付物和下载/访问引用
关键证据
使用过的能力和环境摘要
发生过的等待、审批、修复和人工介入
未完成事项和风险
是否可以保存为技能或复合节点
```
