# 目标拆解方法

## 拆解的目的

拆解不是把一句话机械切成几句，而是把目标转化为一组具有清晰责任、输入、输出、完成条件和依赖的执行单元。

## 四步拆解

### 1. 定义交付物

先问“最终要交付什么”，而不是先问“要调用什么工具”。交付物可以是资源、状态变化、决策、报告、服务或一个可复用能力。

### 2. 建立结果链

对每个交付物反推：

```text
交付物
  -> 必须满足的质量标准
  -> 需要哪些可验证中间结果
  -> 每个中间结果需要哪些前置结果
```

### 3. 建立能力链

对每项工作判断：现有能力是否足够、是否需要组合能力、是否需要委派、是否需要人工、是否需要新建能力。

### 4. 编译执行图

将结果依赖、能力依赖、时序、事件、等待和异常路径合并为图；每个节点必须拥有明确的入参与出参。

## 子目标的最小契约

```text
Subgoal
  objective
  inputs
  outputs
  success criteria
  non-goals
  dependencies
  required capabilities
  risk and authority
  owner execution unit
  failure policy
```

## 粒度判断

一个任务适合作为独立节点，当它满足：

- 可以单独说明输入和输出。
- 可以单独判断成功或失败。
- 可以在不破坏其他节点的情况下重试。
- 具有独立权限、环境或成本边界。
- 用户可能需要单独观察、修改或复用它。

如果一个节点无法解释失败原因、无法独立验证或包含多个不同权限边界，就应继续拆解。反之，过度拆解会增加图噪声；稳定且低风险的链路可以封装为复合节点。

## 动态拆解

初始计划不需要一次达到最终粒度。运行中发现信息不足、失败或用户要求控制时，Agent 可以对节点执行 `expand` 或 `split`，并通过 Graph Patch 替换原节点。原节点运行和新子图运行必须同时保留。
