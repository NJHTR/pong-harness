# 人类协作

## 什么时候询问用户

只有在以下情况提问：

- 缺失信息会改变目标、结果或风险。
- 有多个方案且无法根据偏好安全选择。
- 需要超出当前授权范围的动作。
- 自动验证无法判断关键成功标准。
- 预计失败或成本超过用户可接受范围。

问题应包含背景、影响、候选答案、默认行为和跳过后的后果，避免把系统内部实现细节转嫁给用户。

## 人类节点

```text
Input Request     请求补充数据或说明
Approval Request  请求允许某个具体动作
Choice Request    请求在候选方案中选择
Review Request    请求检查结果或变更
Takeover Request  请求用户暂时接管执行
```

每个请求都有唯一 ID、作用域、过期时间、所需输入、影响范围和恢复位置。

## 介入方式

用户可以暂停、继续、取消、修改节点、修改输入、拒绝补丁、批准单项动作、接管子任务、重跑节点、从检查点恢复或创建新目标。用户介入必须进入运行事件和审计记录。

## 模式切换

自动、协作和手动模式是权限策略，不是三个完全不同的运行时。模式切换前保存检查点；切换后仅对尚未执行的动作生效，除非用户明确批准重新评估整个运行。

## 构建主体与执行主体分离

构建主体决定谁创建和修改目标、画布、节点与连接；执行主体决定谁推进节点、处理输入、验证结果和修复失败。二者分别配置：

```text
构建主体：human / agent / collaborative
执行主体：human / agent / collaborative
```

因此至少支持：

```text
人类搭建 -> 人类执行
人类搭建 -> Agent 执行
Agent 搭建 -> 人类手动调试
Agent 搭建 -> Agent 执行
人机共同搭建 -> 人机共同执行
```

配置可以细化到画布、子图、节点或单次操作。切换主体前保存检查点，切换后的动作仍使用同一运行 ID 和审计链。

## 人工执行

人工执行不是“跳过节点”，而是一个真实执行主体。人工节点需要输入说明、完成条件、结果提交、证据附件、超时和取消方式；提交后与其他节点一样进入验证和下游调度。
