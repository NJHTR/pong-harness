# 安全与治理

## 权限模型

权限是带资源范围的动作授权，不是全局开关：

```text
principal      谁在请求：用户、Agent、节点或外部执行单元
action         要做什么
resource       对什么资源
scope          作用域
purpose        为哪个目标和节点
duration       有效时间
conditions     额外条件
decision       允许、拒绝、等待审批或过期
```

## 信任模型

信任分别评估来源、实现、输入、环境和结果。一个可信来源不代表每次输出都可信；一次验证通过也不代表可以扩大权限。

## 不可信输入

外部内容、用户提供的资源、执行单元输出和自动生成代码都进入数据上下文。它们不能覆盖系统规则、目标约束、权限策略或验证器定义。

## 审批

审批必须绑定到具体目标、图版本、节点配置摘要、资源范围和有效期限。审批结果不可被另一运行或另一配置复用。拒绝、过期和撤销都要传播到等待中的节点。

## 审计

审计记录：目标、计划、图补丁、能力选择、权限决定、输入输出引用、外部调用、人工介入、环境变化、错误和验证结论。敏感内容只保留必要摘要和不可逆指纹。

## 治理不变量

1. 没有权限就不能执行有副作用的动作。
2. 没有证据就不能声明关键目标成功。
3. 没有版本关联就不能恢复或重放运行。
4. 没有取消传播就不能把父任务停止后遗留为失控子任务。
5. 没有敏感信息清理就不能发布为共享技能。
