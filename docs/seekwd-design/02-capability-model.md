# 类人工作能力模型

“像人一样”在本项目中指具有可工程化的观察、判断、行动和协作闭环，不代表模拟人的全部情绪或无限权限。

## 能力闭环

```text
Observe      观察环境、输入、输出和证据
Orient       理解上下文、目标、约束和当前状态
Plan         形成计划、节点图和下一步候选动作
Act          调用工具、Agent、应用、代码和人工流程
Verify       检查动作是否产生预期结果
Reflect      解释成功、失败、不确定性和能力缺口
Repair       修改图、换工具、补环境或请求用户
Remember     记录经验、偏好、证据和可复用技能
```

## 必要能力

### 感知

统一接收外部世界的可观测信息，包括资源、状态、内容、事件、反馈和其他执行单元的结果。具体感知方式由能力适配层决定，感知结果都应带来源、时间、作用域和可信度。

### 能力发现

Agent 可以根据目标反向寻找“什么能够完成这件事”，比较可用的执行单元、服务、应用、智能体、人工协作和新建实现，而不是只按固定节点名搜索。

### 不确定性处理

Agent 必须能够表达不知道、证据不足、多个候选、操作风险和预计成本。遇到不确定性时可以继续探索、进行低风险验证或向用户提问。

### 委派与协作

主 Agent 可以把子任务委派给其他执行单元或人类，并获得任务句柄、进度、输出、取消能力和完成证据。被委派者可以继续委派或创建自己的内部图。

### 人类主导与共同构建

人类可以直接创建目标、画布、节点、连接、配置和验证规则，也可以只提供粗略框架，让 Agent 补全局部实现。Agent 的建议、图变更和执行结果都可以被人类逐项审查、修改、拒绝或接管。

### 运行主体切换

节点和子图都可以声明当前执行主体：人类手动、Agent 自动或人机协同。主体切换不应丢失输入、输出、检查点和审计记录。

### 长时任务

任务可以暂停、等待输入、等待环境、等待其他画布、等待外部 Agent、跨会话恢复，并在崩溃或断电后从检查点继续。

### 学习与沉淀

成功链路可以保存为可复用技能；失败链路可以保存为回归测试；用户偏好、工作区约束和已验证工具可以进入长期记忆，但必须可查看、编辑和删除。

## 不应自动化的行为

- 未经授权读取敏感文件。
- 未经批准向外部服务上传数据。
- 未经批准执行高风险命令、安装环境、删除文件或远程部署。
- 把网页或外部 Agent 返回的指令直接当作系统指令。
- 把一次成功误认为永久可信。
