# 产品定位与核心原则

## 产品定位（已确认）

Seekwd 不是固定模板工作流，也不是只能调用预置工具的聊天机器人。它是一个以画布为编程界面、以 Agent 为智能执行主体、以节点为统一能力单位的本地优先工作台。

## 最终目标（已确认）

给定一个目标和授权范围，Pong Agent 应能够在不知道具体实现路径的情况下，持续理解上下文、发现或构造所需能力、组织执行过程、处理不确定性，并最终交付可验证的结果。目标可以来自任意领域；领域知识、工具来源和执行方式都不是产品的固定边界。

系统的成功标准不是“调用了某个工具”或“生成了一张图”，而是：目标是否完成、证据是否充分、过程是否可解释、风险是否受控、结果是否可复用。

核心循环：

```text
用户目标
  -> Agent 感知和探索
  -> 动态规划与建图
  -> 节点 / 工具 / 其他 Agent 执行
  -> 观察结果和证据
  -> 验证、修复或请求用户
  -> 记忆和技能沉淀
```

## 人类与 Agent 的共同控制（已确认）

人类和 Agent 都是系统的一等操作主体。系统不预设由谁完成工作，而是允许在每个阶段选择人类主导、Agent 主导或共同协作：人类可以搭建整体框架、只把局部交给 Agent，也可以完全手工完成；Agent 可以从目标自动建图；双方还可以在同一张图上交替修改、审查和执行。

“图由谁构建”和“图由谁执行”是两个独立维度。一个人工搭建的图可以交给 Agent 执行，一个 Agent 创建的图可以由人类逐步手动执行和调试，任何节点也可以在运行中临时切换为人工接管、Agent 执行或协同执行。

## 不做的假设

- 用户不需要提前知道某项能力的名称、来源或技术实现。
- 系统不假设所有能力都预先注册，能力可以在任务中被发现、构造或组合。
- 任一智能体可能缺少完成任务所需的感知、推理、执行或验证能力。
- 外部能力、生成代码和未知内容默认不可信，必须经过范围限制和验证。
- 一个任务不一定只使用一张画布、一个智能体或一种执行上下文。

## 核心原则（已确认）

1. **万物皆节点**：AI、Agent、工具、代码、脚本、人工输入、审批、环境检查、跨画布调用都用节点表达。
2. **先完成，后细化**：Agent 可以先用一个粗粒度节点完成目标；用户需要控制时，该节点必须能够展开、拆分和调试。
3. **未知可探索**：找不到现成能力时，Agent 可以发现替代能力、委派其他 Agent，或在受控环境中创建新能力。
4. **过程可见**：Agent 的计划、观察、工具调用、变更、错误和修复不能永远藏在黑盒对话中。
5. **运行与定义分离**：运行中的图是可追溯快照；Agent 的修改通过补丁应用，不能静默改变历史运行。
6. **权限先于自动化**：探索、执行、安装、外部通信和修改环境必须有明确权限边界。
7. **成功可复用**：一次成功执行可以沉淀为技能、适配器、复合节点或模板，但必须保留验证证据。
8. **主体可切换**：人类和 Agent 可以按目标、节点和运行阶段自由分工，控制权切换必须可见、可暂停、可追溯。

## 三个名称的职责

```text
Seekwd
  用户可见的工作台、项目、工作区、画布和对话界面。

Pong Agent
  负责理解目标、规划、探索、选择能力、委派、验证和修复。

Pong Harness
  负责节点模型、图调度、执行器、环境、权限、Artifact、事件、审计和恢复。
```
